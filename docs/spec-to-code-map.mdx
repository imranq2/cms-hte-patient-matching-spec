## Category 2 rules

The specification's [Category 2](/docs/category-2-household-and-individual-rules) section lists ten pairings in its section III.C.4 table: eight household-then-individual pairings, and two relationship-linkage pairings. The specification does not assign them IDs. Its section III.C.8 prose refers to "Rules 13, 14, 15, 16, 34, 35, 37, and 38" for the eight household-then-individual pairings, using numbers from an earlier proposal. Those numbers collide with Category 1 rules 13 to 16, so the library prefixes them with `C2-`.

| Spec section III.C.4 pairing | Library rule | Code |
| --- | --- | --- |
| H-01 (SSN Last 4 + Phone) with I-01 (First Name + DOB) | `C2-13` | `household_rules.py`, `CATEGORY_2_RULES` |
| H-04 (ITIN Last 4 + Phone) with I-01 | `C2-14` | `household_rules.py` |
| H-02 (SSN Last 4 + Email) with I-01 | `C2-15` | `household_rules.py` |
| H-05 (ITIN Last 4 + Email) with I-01 | `C2-16` | `household_rules.py` |
| H-12 (Phone + ZIP) with I-01 | `C2-34` | `household_rules.py` |
| H-13 (Email + ZIP) with I-01 | `C2-35` | `household_rules.py` |
| H-14 (Phone + Street Line) with I-01 | `C2-37` | `household_rules.py` |
| H-07 (Subscriber ID + Phone) with I-01 | `C2-38` | `household_rules.py` |
| Guardian's identity (independently matched under Table 2) + Street Line, with Relationship Linkage (clinical, child-of guardian) + First Name + DOB | `C2-39` | `relationship_linkage_rules.py` |
| Mother's identity (independently matched under Table 2), with Relationship Linkage (clinical, newborn-of mother) + DOB + per-encounter namespace-bound birth-encounter ID | `C2-40` | `relationship_linkage_rules.py` |

The household rows (Table 2-H, H-01 to H-14) and individual rows (Table 2-I, I-01 to I-03) are defined as building blocks in `household_rules.py` (`HOUSEHOLD_ROWS`, `INDIVIDUAL_ROWS`). Only the rules above are built from them.

## Differences to be aware of

These come from comparing the library's README and source comments with specification v3.4.1. They are for the library maintainers to confirm or correct.

- <strong>P(collision) figures.</strong> The library README's rule table lists fuzzy P(collision) of 1.50e-12 for rules 04, 06, and 27, where the specification's Table 2 lists 2e-12. It lists 1.00e-15 for rule 22, where the specification lists ≈0. The library computes its figures from per-field u-values in `collision.py` rather than copying the specification's table.
- <strong>`C2-37`.</strong> A source comment says the household leg should be gated on an institutional-address exclusion (proposal 10, under review) and that this is not yet implemented.
- <strong>`C2-39` and `C2-40`.</strong> The specification's III.C.4 table flags unresolved caveats for both (a dependency discount for the Street Line term in the guardian rule, and the need for a per-encounter identifier in the newborn rule). The library implements them on a best-effort basis and carries the same caveats in source comments.
